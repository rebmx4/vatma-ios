| Элемент | Верхняя граница Y | Нижняя граница Y |
| --- | ---: | ---: |

Ввод адреса в сохранённой иерархии начинается с лишней буквы `я`.
Видео и последний кадр показывают клавиатуру поверх элементов браузера.
Значит, проверки дошли до попытки навигации через перекрытые элементы, а не до
ошибки TLS/сети. Ранее `viewDidLayoutSubviews` только читал `keyboardLayoutGuide.layoutFrame`;
связи Auto Layout с клавиатурой не было, а frame UI остался прежним после её появления.

## Подготовленная правка

- `browserViewport` ограничен safe area сверху/по бокам и верхом `keyboardLayoutGuide` снизу.
  Это связывает изменение доступной высоты с Auto Layout.
- UI и site WebView находятся внутри этой области. Её `bounds` используются и для
  размещения, и для публикуемого размера; прежний раздельный расчёт удалён.
- UI-тест ждёт полного размещения строки и кнопки внутри UI и над клавиатурой/её панелью, проверяет
  точное значение `https://example.com` после ввода и закрытие клавиатуры после отправки.
- Положение элементов повторно проверяется при фокусировке адреса открытого сайта.
  Настоящая загрузка HTTPS, отдельный site renderer и перезапуск приложения сохранены.
- Ревью обнаружило обрезание сверху при высоте viewport меньше 174 pt. Локальный браузер
  воспроизвёл проблему на реальных HTML/CSS при высоте 120/80 px. Компактная панель
  убирает строку профиля, уменьшает строку навигации, а при высоте меньше 95 px оставляет
  адресную строку; после закрытия клавиатуры полная панель возвращается.
- Нативный UI-тест поворачивает устройство с открытой клавиатурой в landscape и обратно
  и проверяет все границы элементов, включая верхнюю.

Подход основан на [Apple: keyboard layout guide](https://developer.apple.com/documentation/uikit/adjusting-your-layout-with-keyboard-layout-guide).
Стандартное поведение guide для docked keyboard сохранено; плавающая клавиатура iPad
не заставляет весь интерфейс следовать за ней.
