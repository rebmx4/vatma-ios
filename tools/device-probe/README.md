# Проверка профиля устройства ATMA

Один и тот же отчёт можно открыть в установленной ATMA и в Chrome на физическом Galaxy A54. Встроенный `BrowserUI/probe.js` рассчитывает на `window.__atmaRequestHeaders`. iOS-приложение это поле не заполняет, а RPC `probe` отключён. `BrowserRenderingFixtureServer.swift` измеряет User-Agent первого запроса и после 302 только в XCTest на loopback HTTP.

## Запуск на тестовом стенде

На хосте с Node.js выполните команду из корня репозитория.

```sh
node tools/device-probe/server.mjs
```

Сервер слушает `127.0.0.1:8765`. Для другого порта задайте `ATMA_DEVICE_PROBE_PORT`. На выделенном HTTPS-origin тестового стенда направьте путь `/atma-device-probe/` и весь его префикс на этот адрес, сохранив путь, заголовки запроса и заголовки ответа `Location` и `Accept-CH`. Для проверки перехода между сайтами используйте второй HTTPS-origin с тем же маршрутом. Используйте действительный сертификат, отключите access log для префикса и оставьте маршруты открытыми только на время измерения. Клиенты открывают `https://<хост-стенда>/atma-device-probe/`.

Ведите версии ATMA, iOS, Android и Chrome отдельно от отчёта. Откройте адрес в новой обычной вкладке установленной ATMA, затем в инкогнито с «Это устройство» и с выбранным Galaxy A54. На физическом Galaxy A54 откройте адрес в новом сеансе Chrome инкогнито. Для других профилей повторите тот же сценарий. Для проверки наследования откройте адрес вручную в новой приватной вкладке и по ссылке «Открыть дочернее окно» из отчёта. Для перехода на другой сайт откройте адрес второго тестового origin из уже загруженной страницы.

- `firstNavigation` фиксирует заголовки до отправки 302. `navigationAfter302` фиксирует запрос документа после перенаправления. Пустое или ранее посещённое окружение Chrome может давать разные результаты из-за сохранённого opt-in на origin.
- Документ отвечает `Accept-CH` и выполняет ещё один same-origin запрос для `afterAcceptCH`. Соблюдение запроса подсказок зависит от браузера. Chrome объясняет, что подробные Client Hints могут отсутствовать даже после opt-in. [User-Agent Client Hints в Chrome](https://developer.chrome.com/docs/privacy-security/user-agent-client-hints)
- `page.userAgent` фиксирует текст, который видит JavaScript. Код `SM-A546B` в User-Agent и поле `page.clientHints.model` измеряются отдельно. `null` означает «не предоставлено». Пустое HTTP-значение модели `""` сохраняется как присланное браузером. Размеры `screenCSSPixels`, `layoutViewportCSSPixels` и `visualViewportCSSPixels` отображаются отдельно. `screenCSSPixels` может отражать выбранный профиль, а две области просмотра относятся к текущей странице. [Спецификация User-Agent Client Hints](https://wicg.github.io/ua-client-hints/)
- Для проверки изоляции нажмите «Поставить тестовые метки» в одном сеансе. Повторно откройте адрес в ручной и дочерней вкладке того же сеанса и в явно отдельном сеансе. Сравните два флага `syntheticMarks`. `true` означает наличие тестовой метки, `false` её отсутствие, `null` означает недоступное хранилище. После закрытия сеанса перепроверьте в новом. На обычной вкладке удалите метки кнопкой на странице.

Отчёт показывает только User-Agent, нужные UA Client Hints, указанные свойства окна и флаги собственных меток. Сервер держит в памяти до 32 незавершённых прогонов. Для выдачи результата отводится две минуты. Прямой URL результата одноразовый. Для повторного запуска используйте ссылку «Повторить».

```sh
node --test tests/device-probe.test.mjs
```
