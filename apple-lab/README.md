# ATMA Apple Lab

Windows-панель настоящего Apple Simulator на GitHub Mac. Откройте `Start-Apple-Lab.cmd` в корне проекта.

1. Выберите iPhone или iPad и нажмите **Подключить**. В центре показан текущий этап, справа — время подготовки. Дождитесь живого экрана; **Отменить запуск** завершает подготовку.
2. Кнопка становится зелёной после получения и отображения живого экрана и подключения управления.
3. Управление: нажатия и свайпы мышью, колесо для прокрутки, клавиатура при фокусе на экране. Alt + перетаскивание — два пальца для масштаба. Для русского текста используйте **Вставить текст**.
4. **Отключить**, отмена подготовки или закрытие окна останавливают сеанс. Дождитесь окончания остановки перед новым подключением.

GitHub создаёт новый Mac для каждого сеанса. Подготовка занимает несколько минут и зависит от очереди и первого запуска iOS. Если версия приложения, Xcode и параметры сборки совпадают, используется готовая ATMA.app из кэша. При изменении исходников приложение собирается заново. Запуск iOS идёт параллельно с подготовкой приложения.

Кэш содержит только сборку Simulator и её манифест, без данных устройства. Одна сборка подходит для iPhone и iPad. Она сохраняется до интерактивного сеанса, поэтому обычное отключение не мешает повторному использованию. Кэш может быть удалён GitHub; тогда следующая подготовка снова включает сборку. Лимиты хранения репозитория не увеличиваются.

Снимки сохраняются в `out/apple-lab/screenshots` на D:. Профиль браузера, журналы и сведения о завершённых сеансах находятся в `out/apple-lab`. Локальный сервер слушает только `127.0.0.1:4186`. Для повторного открытия используется тот же launcher; новый сеанс автоматически не запускается.

## Источник приложения

Репозиторий: `rebmx4/vatma-ios`. По умолчанию приложение берётся из ветки **atma-browser-testflight**, инструменты просмотра — **apple-simulator-lab**. При каждом подключении панель получает точный SHA приложения с GitHub и передаёт его сборщику. Чтобы проверить правку, закоммитьте и отправьте её в исходную ветку, затем подключитесь заново. Незакоммиченные файлы Windows в удалённую сборку не попадают. В панели «О сеансе» видны SHA и задача Actions.

Приложение собирается для `iphonesimulator`, без подписи и загрузки в магазин. Используются те же UIKit, WKWebView, ресурсы и project.yml, что и в нативной версии ATMA. Этот workflow не меняет номер TestFlight-сборки и не обращается к секретам подписи. Успех сборки не заменяет проверки поведения приложения.

## Ограничения

- Одно устройство за сеанс; новый Mac и чистый Simulator при следующем подключении. Данные устройства не сохраняются между сеансами.
- GitHub job ограничен 60 минутами, включая подготовку. При отсутствии подтверждённого соединения удалённый просмотр завершается по lease за 60 секунд после готовности канала; при недоступном GitHub API это независимый путь остановки.
- Стандартный `macos-26` в публичном репозитории. Панель отказывается запускать настроенный репозиторий, если он стал приватным; смена аккаунтов для обхода квот не используется.
- Видео MJPEG и управление передаются через Cloudflare Quick Tunnel. Задержка и доступность зависят от сети, очереди GitHub и внешнего сервиса. Это среда разработки, а не постоянный удалённый Mac.
- Simulator использует настоящую среду iOS, но не воспроизводит физическое оборудование iPhone/iPad полностью. Камера, модем, производительность, энергопотребление, отдельные системные возможности и окончательная проверка перед выпуском требуют реальных устройств.

## Реализация и проверка

Node 24+, Git и уже сохранённый вход GitHub через Git Credential Manager. GitHub-токен читается только в память локального процесса и не передаётся веб-странице. В открытые inputs Actions передаётся только одноразовый **публичный** ключ Ed25519. Все запросы к удалённому шлюзу подписаны; подпись привязана к сеансу, времени, nonce, методу, пути и телу. Повторные запросы отклоняются. Внешний шлюз не публикует shell, файловый API или установку произвольных приложений.

Адреса Quick Tunnel разрешаются через HTTPS DNS Cloudflare только внутри локального контроллера: системный DNS на этом ПК не разрешал новые домены trycloudflare.com. Host/SNI и проверка TLS-сертификата сохраняются; системные настройки Windows не меняются. Ответы DNS с локальными или частными адресами отклоняются.

`npm ci --prefix apple-lab --ignore-scripts --no-audit --no-fund` и `npm test --prefix apple-lab` выполняются с `TEMP=D:\tmp`, `TMP=D:\tmp`, `npm_config_cache=D:\npm-cache` на Windows. Единственная локальная зависимость — закреплённый `ws`. Mac устанавливает закреплённый `serve-sim` из отдельного lockfile; архив cloudflared проверяется по SHA-256.

Workflow `.github/workflows/atma-apple-preview.yml` должен быть зарегистрирован на default branch. Запуск всегда выполняется на ветке инструментов; приложение checkout-ится отдельно по точному SHA. Остановка использует уникальный ID и название собственного сеанса и не отменяет проверки или TestFlight.
